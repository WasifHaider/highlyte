# Video upload (piece 3b): design

Date: 2026-11-09. Status: approved in chat.

## Why

YouTube sometimes rate-limits every download route at once. Upload is the
fallback that always works: a teammate downloads the video on their own
machine (or has the original recording) and uploads it. It also covers
videos that are not on YouTube.

## Constraints

- The public entry point is Cloudflare Tunnel, which rejects request bodies
  over 100 MB. A 1-2 GB podcast cannot go through the backend in one request.
- Clip media already lives in Cloudflare R2 (`backend/storage.py`), so the
  backend has R2 credentials and R2 has no egress fees.
- Max upload size: 5 GB. Accepted extensions: `.mp4 .mov .mkv .webm .m4v`.
- An uploaded original is kept in R2 until its project is deleted.

## Flow

1. Browser: `POST /api/uploads` with `{filename, size, contentType}`.
2. Backend validates size (1 byte to 5 GB) and extension, makes an upload id
   (12 hex chars), starts an R2 multipart upload at
   `uploads/{id}/source{.ext}` with object metadata `filename` and `team`,
   and returns `{uploadId, partSize, partUrls}`: one presigned `UploadPart`
   URL per 64 MiB part, valid for 6 hours.
3. Browser PUTs the parts straight to R2, three at a time, retrying a failed
   part up to 3 times, and reads each part's `ETag` response header.
4. Browser: `POST /api/uploads/{id}/complete` with `{parts: [{partNumber,
   etag}], language}`. Backend completes the multipart upload, creates a Job
   with `url = "upload:{id}"`, starts `_run_pipeline`, returns `{job_id}`.
5. Cancel: `DELETE /api/uploads/{id}` aborts the multipart upload.

Pending uploads are tracked in memory (`id -> team, key, R2 upload id,
filename`). A restart forgets them; the R2 lifecycle rule cleans up the
abandoned parts. `complete` and `DELETE` return 404 for an id that is
unknown or belongs to another team.

## Backend seam

Every pipeline step reads the source through `ingest.ingest(job.url)` and
`ingest.SectionSource(job.url, ...)`. Both hand off to a new module,
`backend/pipeline/uploads.py`, when the url starts with `upload:`:

- `uploads.ingest_upload(upload_id, cache_dir)` returns a `VideoMeta`:
  - ensures the original is in the cache as `up-{id}.source{.ext}`,
    downloading it from R2 if missing (touching it if present, for the
    cache sweeper);
  - extracts audio to `up-{id}.audio.m4a` with ffmpeg (cached);
  - reads duration with ffprobe;
  - title = original filename without extension (from R2 metadata),
    channel = "Uploaded video", video id = `up-{id}`;
  - makes a poster JPEG with ffmpeg at 10% of the duration, uploads it to
    `uploads/{id}/thumb.jpg` once, and sets `thumbnail_url` to
    `/api/uploads/{id}/thumb.jpg`.
- `uploads.source_path(upload_id, cache_dir)` returns the local original
  (re-downloading from R2 if the sweeper removed it). `SectionSource` uses
  it instead of a YouTube download; cutting already re-encodes to H.264.
- `GET /api/uploads/{id}/thumb.jpg` streams the poster from R2 for members
  of the team that owns a job with that source.

## Safety and cleanup

- `/api/generate` rejects urls starting with `upload:`, so upload sources
  cannot be submitted by hand (links without a scheme still work).
- `_purge_job` deletes `uploads/{id}/source*` and `thumb.jpg` when the job's
  url is an upload, unless called with `keep_upload=True`.
- `retry_failed` reuses the same `upload:` url and purges the old job with
  `keep_upload=True`.
- Without R2 configured, the upload endpoints return 503 and
  `/api/health` reports `uploads: false`; the UI hides the button.

## UI

- `useGenerate` gains `onUpload(file)`, shared by the Home hero and the top
  bar. A new `uploader.js` service does the part uploads with progress.
- Home hero and top bar: an "Upload a video" button next to the link field;
  the Home hero also accepts drag-and-drop.
- While uploading: file name, percent, speed, and Cancel. Then it routes to
  the job page like a link does.
- Errors: "File is over 5 GB.", "That file type isn't supported. Use MP4,
  MOV, MKV, WebM or M4V.", "Upload failed. Check your connection and try
  again."

## One-time setup (docs/video-upload-setup.md)

- R2 bucket CORS: allow `PUT` from the app's origin and
  `http://localhost:6100`, allow header `content-type`, expose `ETag`.
- R2 lifecycle rule: abort incomplete multipart uploads after 1 day.

## Testing

- `tests/test_uploads_api.py`: create validates size and extension; create,
  complete and abort with a fake R2 client; other team gets 404; complete
  starts a job with an `upload:` url; `/api/generate` rejects `upload:`;
  503 without R2; purge deletes the original, retry keeps it.
- `tests/test_uploads.py`: `ingest_upload` and `source_path` with a fake R2
  client and a tiny video generated by ffmpeg; cached files are reused.
- Frontend: `npm run build`.

## Out of scope

Resuming an upload after a page reload, uploads from a URL other than
YouTube, and per-team storage quotas.
